Nothing here is simplified to the point of being wrong — where a caveat matters, it sits in the same sentence as the claim, not in a footnote.

Two figures are worth reading before anything else, and everything later leans on them: V-4 shows how to read a price chart from scratch, and V-6 shows how to read the code excerpts. Section 01

The Big Picture — what this research actually asks

Before any formula: what question is on the table, and what would count as an answer.

The one-sentence version

Bitcoin's price swings violently. This study asks whether a fixed set of mechanical rules — no human judgment, no discretion — could have picked entry and exit points on Bitcoin over four years and beaten a coin flip, and whether the structural “quality” of the price zones it traded off mattered.

The formal research question

This is how the paper states it. It looks dense; it is six ideas stacked together, and the table below takes them apart one at a time.

From the paper, §0

Does a rule-based entry/exit strategy that gates MACD and KDJ momentum signals through Smart Money Concepts (SMC) Order Block structural zones produce a historical win rate and return on BTC/USDT 4-hour candles that departs from a zero-edge (50% win probability) null model, and does OB “quality” (a 5-criterion structural score) modulate that departure?

Phrase in the questionWhat it means plainly
rule-basedA computer program decides. Every condition is written down in advance. Run it twice, get the same answer twice.
MACD and KDJ momentum signalsTwo standard indicators calculated from price history. They try to detect “this move is losing steam” or “this move is picking up.”
gates … through Order Block zonesThe momentum signal alone is not enough. Price must also be sitting inside a specific structural price zone before a trade is allowed. The zone acts as a filter — a gate.
BTC/USDT 4-hour candlesThe price data. Each row summarises 4 hours of Bitcoin trading: open, high, low, close, volume.
departs from a zero-edge (50%) null modelThe comparison baseline is a coin flip. If the rules have no skill, roughly half the trades win. The test asks whether the real result is far enough from half to be surprising.
does OB “quality” modulate that departureEach zone gets scored on five structural features. Second question: do the higher-scoring zones actually produce better trades?

What this study is, and what it is not

Backtest
Running a trading rule over price history that already happened, to see what it would have done. It is a simulation, not a track record.
Pre-registered
The rules and their numeric settings were fixed before measuring results, and never adjusted afterward to make the results look better. This is what separates a test from a fishing expedition.

Why “no tuning” is the central commitment

Overfitting (also “curve-fitting”)
Adjusting rules until they fit one particular stretch of history beautifully. The result then describes that history rather than revealing anything about markets, and it usually falls apart on new data. Overfitting is the single most common way a backtest becomes worthless, and it leaves no visible trace in the final numbers — which is why it has to be prevented in advance rather than detected afterwards.

If you are allowed to keep adjusting the rules until the backtest looks good, you will always produce a good-looking backtest — and it will mean nothing. The repository enforces this structurally: parameters are constants at the top of the code, a golden-master regression test fails if any locked result moves, and every headline figure is checked against a committed list on every run.

2.2  The three indicators

An indicator is a number calculated from recent price history, used to summarise something a chart shows visually. This strategy reads three.

First, a one-minute primer: how to read the dark code boxes

From here on, every rule in this study is shown twice — once in plain English, and once as the actual lines from the program that ran it. The code is included so that nothing has to be taken on trust: you can put the sentence and the line side by side and check that they say the same thing. You do not need to know how to program to use these boxes. Five ideas cover everything that appears in them, and V-6 labels all five on a real line from the file.

Program / code
A list of instructions written in a language the computer follows exactly, in order, top to bottom. The language used here is called Python.
Variable
A name that holds a value, so it can be reused later. risk = close - stop means “work out close minus stop, and from now on call that answer risk.”
Function
A named, reusable block of instructions. Written with brackets after the name: compute_indicators(df) means “run the block called compute_indicators, handing it the thing called df.” The thing handed in is called an argument.
Table and column (df, df["close"])
df is the whole spreadsheet of price data — 8,767 rows, one per candle. df["close"] is one whole column of it: every closing price, top to bottom. Doing arithmetic on a column does it to every row at once, which is why one short line can describe 8,767 calculations.
True / False (a “boolean”)
A yes/no value. Every quality criterion and every entry filter in this study ends up as one of these two.
Comment (#)
Any text after a # is a note written for human readers. The computer skips it entirely. That is exactly why a comment can be wrong while the code is right — a situation this project actually hit, and discloses below.

MACD (12, 26, 9) — “is the momentum turning?”

Take two exponential moving averages of the closing price — a fast one (12 bars) and a slow one (26 bars). Subtract them. When the fast average pulls away from the slow one, price is accelerating; when they converge, it is stalling. A third average (9 bars) of that difference is the “signal line,” and the gap between them is the histogram. The strategy reads the histogram only.

Exponential moving average (EMA)
A rolling average that weights recent bars more than old ones, so it reacts faster than a plain average.
Causal
adjust=False in the code means bar t's value uses only bars up to t. No peeking ahead.

KDJ (9, 3, 3) — “is this overbought or oversold?”

Ask where the current close sits inside the high/low range of the last 9 bars, as a percentage (0 = at the bottom of the range, 100 = at the top). That is the RSV. Smooth it once to get K, smooth K again to get D, then compute J = 3K − 2D, an amplified line that overshoots and so reacts sooner.

ATR (14) and ATR (200) — “how violent is this market right now?”

For each bar, compute the true range: the largest of (high − low), |high − previous close|, |low − previous close|. Average it over 14 bars for short-term volatility, and over 200 bars for a long-term baseline. ATR is in price units, so “1.5 × ATR” means “1.5 typical bar-moves of room.”

ATR does double duty: ATR(14) sizes stop-losses and drives two exit rules; ATR(200) is the yardstick for the volatility-regime filter and for two of the five quality criteria.

Precision note — a wrong comment, disclosed

A comment in the code says the ATR uses Wilder's smoothing (RMA), but the executed line is a plain rolling mean — a simple moving average. The paper correctly describes the SMA. The comment is wrong; the code and the paper are right. This is disclosed, not hidden, and it changes no figure. Source: research_analysis.py:593-604; paper §1.2.

2.3  Order Blocks — the structural gate

This is the part of the strategy that is not a standard indicator, and the part most worth a diagram.

Order Block (OB)
The last candle before a decisive move that breaks through a prior price level. The idea comes from Smart Money Concepts trading: large players accumulated positions in that candle's price range, so if price returns there later, that range may act as support or resistance again. In this study it is simply a price zone with a birth certificate — an origin bar and a confirmation bar.
Smart Money Concepts (SMC)
A family of chart-structure trading ideas focused on where large orders likely sit. The detection code here is a faithful translation of the widely-used LuxAlgo TradingView indicator, so the zone definition is not this study's invention.
DEMAND OB / SUPPLY OB
A zone below price, a candidate place to buy (go LONG) / a zone above price, a candidate place to sell short.

How one is detected, in four steps

  1. Find a pivot. A bar is a pivot high if its high is strictly greater than every high in the bars that follow it, up to the current bar. It can only be confirmed after those later bars exist — which is exactly why the confirmation lag matters.
  2. Watch for a structure break. If a later close crosses that pivot level, structure has broken. If it continues the existing trend it is a Break of Structure (BOS); if it reverses the trend it is a Change of Character (CHoCH).
  3. Name the Order Block. Scan back from the pivot to the breaking bar and pick the extreme candle. Its high/low become the zone's top and bottom.
  4. Score it on five quality criteria (§2.4).

Two bar indices matter and are easy to confuse:

IndexName in codeWhat it is
The origin candleob_barWhere the zone's own extreme candle sits
The confirmation candlecreated_atWhere the breakout candle closes — the OB is not usable for entry until strictly after this bar

The zone dies two ways: it expires after 500 bars (MAX_ORDER_BLOCK_AGE_BARS, about 83 days), or price closes straight through it (mitigated_at, which the code calls being mitigated — the zone has been used up and is retired from the list of live candidates).

Two passes run over the same price series with different pivot lookbacks — how many bars back the code looks when deciding whether a bar was a genuine turning point. A short lookback (5 bars) notices small local wiggles; a long one (50 bars) only notices major turns. Both passes run, and both contribute Order Blocks to the same pool.

2.4  The five orthogonal quality criteria

Orthogonal
Independent of each other. Each criterion is evaluated on its own and can be true or false regardless of the others. This matters because of a real bug that was found and fixed (§2.7): the original scoring scheme made higher-scoring zones nested subsets of lower-scoring ones, so “higher quality” and “different sample” were tangled together and no clean claim could be made.

The five booleans are summed into a 0–5 quality integer. That integer is used only as an entry filter threshold (quality >= min_ob_quality) — never as a “higher is better” ordinal claim in the analysis. That restriction is the direct consequence of bug 1.

A retired analysis, mentioned so its absence isn't mistaken for an omission

An earlier version of this project went further and asked a second question: does each individual criterion, on its own, predict whether a trade wins? Answering it meant splitting the 27 trades into subgroups — the trades taken on zones where Displacement was true, versus the rest, and so on for all five — and running a comparison test on each split.

That entire programme was deliberately deleted from both the code and the paper on 2026-08-27, for a reason worth stating plainly: the subgroups were far too small for the answers to mean anything — some contained as few as four trades. A test run on four observations cannot distinguish a real effect from noise in either direction, so reporting its result, positive or negative, would have been misleading. The paper now reports only the core win-rate claim and the three-arm ablation (§6.1), and this guide follows the current paper rather than reconstructing the retired tests. Their absence here is a decision, not an oversight.

2.5  The trading rules

LONG / SHORT
Betting price goes up — buy, then sell higher. / Betting price goes down — sell borrowed coin, buy it back cheaper.
Stop-loss (SL)
A pre-set exit price that caps the loss if the trade goes wrong.
Take-profit (TP)
A pre-set exit price that banks the gain.
Reward-to-risk ratio (R:R)
Potential gain divided by potential loss. R:R = 1.5 means risking $1 to make $1.50. Trades below the minimum are refused before they are taken.
Entry / exit
The moment a position is opened / the moment it is closed. Between them the trade is “open” and its value moves with price; once it is closed the result is fixed and cannot change.
Position
An open bet. Having a position means money is currently exposed to the market. This strategy holds a position only 2.63% of the time (§5.2) — it spends almost all of its life holding nothing.

Two of those seven filters are worded in a way that reliably confuses first-time readers, so they get their own figure. Filter 5 rejects a trade when volatility is ordinary — which sounds backwards until you see it drawn. Filter 4 accepts only a middle band of momentum acceleration, rejecting both ends.

Rung 1 — the trailing 50% retrace — fired on 8 of the 27 trades, behind the ATR-move exit's 9 and level with the KDJ-reset exit's 8. It is the only exit rule whose behaviour depends on the trade's own history rather than on a fixed price level decided at entry, so it is the one worth seeing drawn.

The paper presents its own correction history as evidence of process. This is a defence strength, not a liability: a study that finds and reports its own errors is a study that was actually checked.

Lookahead (data leakage)
When a backtest accidentally uses information that would not have been available at that moment in real time. It is the classic way a backtest flatters itself. Bug 3 was a genuine, if small, instance.

The no-lookahead proof, independent of the bug narrative

The truncation check works like this: pick a bar somewhere in the middle of history, hide everything after it, recompute an indicator, and confirm you get exactly the same value as when the whole four years were visible. If the indicator had been secretly reading ahead, the two answers would differ. This was done for 36 sampled bars across 5 indicator columns — 180 checks, 180 matches.

Separately, runtime assertions sit permanently at the two places in the code that search forward through time (research_analysis.py:813, :843). An assertion is a line that states something which must be true and deliberately crashes the program on the spot if it ever is not — a tripwire rather than a report. Because they live in the code rather than in an audit script, a future change that reintroduced lookahead would fail on the very next run instead of waiting to be noticed. None has fired in any run since.

Section 03

Codebase Architecture

How raw price data becomes a number in the paper — every stage, every function, and why each one exists.

3.1  The one-file design, and why

Everything — the backtest engine, the statistics, the database layer, and the dashboard's web server — lives in research_analysis.py, a single file of about 5,400 lines at the repository root, organised into eight numbered sections.

This was a deliberate consolidation. The same logic used to be spread across roughly fifteen files, each one loading the others and passing results between separate program runs. For a research artifact, one file a reviewer can read top to bottom beats fifteen convenient ones: there is exactly one definition of the backtest, so there is no possibility of two versions quietly disagreeing.

The superseded originals were moved to a legacy_pre_consolidation/ folder kept on disk but excluded from the project's tracked history — available if anyone wants to look, but no longer part of the running system. It was a reorganisation, not a change of strategy (programmers call this a refactor), and that claim is not asserted on trust: the four core pieces of the engine were run before and after the move and produced results that matched the stored copies exactly, digit for digit.

Section 04

The Statistical Toolkit

Every test here answers one question — could this have happened by chance? They differ only in what “this” is.

Every statistical test in this section works the same way, and it is worth stating the shape once before any of them appear. You begin by assuming the boring explanation is true — that the strategy has no skill whatsoever and each trade is a coin flip. Statisticians call that assumption the null hypothesis, or the null model. Then you ask: if that were true, how often would pure chance hand me a result at least as good as the one I actually got? If the answer is “very often,” the result is unremarkable. If the answer is “almost never,” then either something unusual happened or the boring explanation is wrong. That fraction is the p-value, and every test below is a different way of computing it for a different question.

The one thing that catches people out

A test never proves the strategy works. It only reports how poorly the boring explanation accounts for what was observed. Ruling out “pure luck” is not the same as ruling in “real, repeatable skill,” and this guide never treats it as though it were.

4.1  The p-value — define this before any test

4.2  The binomial test — “better than a coin flip?”

Question: with 27 trades and 19 wins, how surprising is that if each trade were a 50/50 coin flip?

Plain mechanism: count every possible way to get 19 or more heads in 27 flips, add up their probabilities. That total is the p-value.

p = Σk=19..27 27k (0.5)27 = 0.0261

One-sided vs two-sided — one-sided asks “is it better than chance?”; two-sided asks “is it different from chance, in either direction?” The paper uses one-sided as its primary figure because the hypothesis was directional and pre-registered (the strategy was built to beat the null, not merely to differ from it), and reports the more conservative two-sided value alongside.

Tests considered and deliberately not used

Fisher's exact test and Welch's t-test compare two independent samples. The strategy-vs-DCA and strategy-vs-buy-and-hold comparisons in §5 each involve exactly one realized equity curve per side — one price path, not a sample of independent outcomes — so there is no legitimate sampling distribution for a two-sample test to read. Applying one anyway would manufacture a p-value out of an arbitrary choice about what counts as an "observation." The paper's Data Analysis section records this reasoning and states plainly that neither test appears anywhere in the paper.

4.3  Pearson and Spearman — “do longer holds earn more?”

Pearson r measures how well a straight line fits the relationship between two measurements. It runs −1 (perfect inverse) to +1 (perfect direct), with 0 meaning no linear relationship. It is sensitive to outliers.

Spearman ρ does the same on ranks — 1st longest, 2nd longest, and so on. It catches any consistently-increasing relationship, straight-line or not, and one extreme trade cannot dominate it.

Both are reported, deliberately. If the two agree in sign and significance, the association is not an artifact of a few extreme trades.

4.4  Bootstrap resampling — “how much could this have wobbled?”

The problem: the study has exactly one set of 27 trades. What would a different 27 have looked like? There is no second history to check.

The bootstrap answer: treat those 27 outcomes as a stand-in for the population and draw new 27-trade samples from them, with replacement — some trades appear twice, some not at all. Do that 10,000 times, total each sample, and look at the spread of totals. The middle 95% of that spread is the confidence interval.

The bootstrap captures uncertainty about which of these trades you happened to get. It cannot capture uncertainty about which trades would have existed at all under a different price history. It is a real but bounded stress test.

4.5  Risk metrics — Sharpe, Sortino, max drawdown

Not hypothesis tests. Descriptions of the shape of a return stream.

Sharpe ratio
Average return divided by total volatility, annualised. “How much return per unit of bumpiness.” Higher is better.
Sortino ratio
The same, but only downside volatility counts in the denominator. Upside surprises are not penalised. Usually the more appropriate measure for a strategy with an asymmetric payoff.
Maximum drawdown
The worst peak-to-trough fall the equity curve ever suffered, in percent. What it would have felt like to hold at the worst moment.
Time in market
The share of all bars during which a position was actually open. This is the number that makes the strategy's Sharpe incomparable to a buy-and-hold Sharpe, and it must appear beside them every time.
Equity curve
Account value drawn as a line over time. All three metrics above are just different ways of describing the shape of that line: how bumpy it is, how bumpy it is on the way down only, and how far it ever fell below its own best point.
Annualised
Rescaled to a “per year” basis so periods of different length can be compared. It does not mean the strategy actually earned that in a year.
Disclosed assumption

Both Sharpe and Sortino here are computed with an implicit risk-free rate of zero — the excess-return numerator is the raw mean return, not mean minus a T-bill yield. Standard for crypto backtests and disclosed in docs/MATH_CORRECTNESS_AND_COMPREHENSION.md, but it should be stated, since a non-zero risk-free rate would lower every Sharpe reported here.

4.6  The ablation empirical p-value — “could a lucky draw explain the gate's edge?”

Question: the OB-gated baseline (27 trades) beats each ungated ablation arm (140 or 138 trades, §6.1) by a wide margin on average return per trade. But the baseline is also a much smaller sample. Could a 27-trade slice drawn from the same ungated pool, just by luck, have looked as good as the real baseline — making the apparent edge a sampling accident rather than something the Order Block gate actually does?

Plain mechanism: treat one ungated arm's full trade pool (its own 140 or 138 real outcomes) as the population. Draw a random sample of 27 from it, with replacement — the same size as the real baseline — and record that sample's average return. Repeat this thousands of times. That builds a picture of “what a 27-trade slice of this arm's own trades typically looks like.” Then ask: what fraction of those thousands of slices did at least as well as the real baseline's actual average return? That fraction is the p-value — the same “how surprising would this be by chance” logic as §4.1, applied between two arms instead of against a coin flip.

Not the same question as §4.4's bootstrap

Section 4.4's bootstrap resamples the baseline's own 27 trades to ask how uncertain the baseline's own result is (a within-arm question). This one resamples a different, ungated arm's trades at the baseline's sample size to ask whether that arm's own trade quality could plausibly explain the baseline's result (a between-arm question). Same resampling mechanic, different population, different question.

Result (2026-08-20 reconstruction, live-verified against artifacts/ablation_reconstruction.json): for the swing-pivot ungated arm, resampled 27-trade average returns have median −0.17%, 95% range [−1.26%, +0.89%], and only 0.9% of 2,000 resamples matched or beat the real baseline's +1.12% average — empirical p = 0.009. For the flat-ATR arm the figures are median −0.10%, range [−1.22%, +1.02%], p = 0.0135. Both point the same way: if the ungated arm's own trades were the true population, a 27-trade sample this good would be rare. Caveat: because the ablation reconstruction itself diverges from the paper's originally published 140/138-trade figures (§6.1, D1), these specific percentiles describe the reconstruction, not a number independently re-derivable from the paper's own uncommitted script.

5.3  Cost sensitivity — where the significance claim breaks

Every real trade costs something to place, and the headline +30.31% is a gross figure — before any of those costs. There are two of them:

The exchange fee
Binance charges 0.05% per side on this kind of order. Since every trade has to be both opened and closed, that is 0.10% per round trip — “round trip” simply meaning in and out again.
Slippage
The gap between the price you expected and the price you actually got, because the market moves in the instant your order arrives. It is not a fee anyone charges; it is friction. Modelled here at a conservative 0.05% per side, so another 0.10% per round trip.

Together that is a flat 0.20% subtracted from every trade. It is a small number. It is also enough to change the study's headline statistical conclusion, which is why it gets its own section:

The asymmetry worth explaining

A flat per-trade drag subtracts the same constant from every trade's return. That shifts the average return and can flip individual trades from win to loss — which is exactly why the win rate and binomial p move — but it cannot change how strongly hold time and return move together, since Pearson r and Spearman ρ (§4.3) are unaffected by adding a constant to every value of one variable. So the correlation story is robust to costs; the win-rate story is not. Both facts belong in the same paragraph.

Section 06

Discussion — and the two disclosed divergences

Two places where the numbers do not line up, why each one exists, and why neither sinks the conclusion.

6.1  D1 — The ablation reconstruction gap

Ablation
Remove one component and re-run, to see how much that component was contributing. Standard practice — the same idea as removing one ingredient to find out what it was doing to the recipe.

The ablation design — three arms

ArmEntry ruleWhere the stop goesNWin rateTotal return
1 — OB-gated baselineOB touch + MACD/KDJ/ATROB boundary − 0.5 × ATR2770.37%+30.31%
2 — Indicators only (flat-ATR stop)MACD/KDJ/ATR onlyclose − 1.5 × ATR14060.00%−14.63%
3 — Indicators only (swing-pivot stop)MACD/KDJ/ATR only5-bar swing pivot ± 0.5 × ATR13855.07%−25.50%

What it establishes: without the Order Block gate, the same indicator conditions fire five times more often and lose money.

Arm 3 exists to close one specific loophole. With only arms 1 and 2, two explanations for arm 2's failure sit tangled together and neither can be credited on its own — statisticians call this being confounded. Perhaps the ungated arm failed because it picked bad trades; or perhaps it picked perfectly good trades and merely put its stop-loss in a worse place. Arm 3 keeps the entries of arm 2 and swaps in a completely different, structure-anchored stop. The trade count barely moved (138 against 140, a difference of 1.4%) and performance was not rescued. Stop placement is therefore ruled out, and what remains is that the gate's contribution is about which trades get taken at all.

The disclosed problem

No committed script in this repository reproduces the published 140/138-trade win rates from scratch. The script that originally produced them was never committed.

A best-faith reconstruction was built from the documented design. It reproduces the trade counts exactly — but not the per-trade outcomes.

Why this is disclosed rather than fixed, and why it does not sink the conclusion

  1. The exact N match is informative. 140 and 138, hit exactly, means the entry-side logic is faithfully reproduced. The gap is somewhere post-entry.
  2. It was investigated, not merely noted. Twenty combinations were tested and ruled out (see V-38).
  3. Fixed-2R and fixed-3R give identical results, which proves the take-profit is almost never the operative exit at this distance — so the take-profit formula cannot be the cause. This matches V-17: the hard take-profit fired zero times in the baseline too.
  4. An independent earlier reconstruction failed the same way, thirteen days earlier, arrived at separately. Converging evidence.
  5. The conclusion does not depend on the exact win rates. Both the locked figures (60.00% / 55.07%) and the reconstruction (47.14% / 43.48%) say the same thing: the ungated arms take five times as many trades and lose money. The direction and magnitude of the finding are unchanged.
  6. Two candidate explanations remain untested and are named as such (see V-38, right panel).
How to present this to a panel

It converts “we can't reproduce it” into “we ruled out the twenty most likely mechanical causes and named exactly what remains.” That is a stronger position, not a weaker one. The locked figures remain the paper's canonical numbers; the reconstruction exists to document the gap, not to replace them.

6.2  D2 — The bootstrap resample-count mismatch

The observation: the paper reports a 95% confidence interval on total return of [+5.99%, +54.99%]. The interactive dashboard shows [+7.48%, +54.46%]. Same data, same seed, different numbers.

SurfaceB (resamples)SeedRandom generator95% CI
Python — run_bootstrap_ci() (paper canonical)10,00042numpy default_rng[+5.99%, +54.99%]
JavaScript — statsCompute.ts2,00042mulberry32[+7.48%, +54.46%]

Why the gap exists: the bootstrap is a random procedure. Its percentile estimates settle down as the number of resamples grows. Ten thousand draws land in a slightly different place than two thousand. Both intervals are individually correct estimates of the same thing.

Why the dashboard uses fewer: it runs in the browser, live, on every page load. Two thousand resamples is a responsiveness choice.

The root cause was proven, not assumed

The dashboard's mulberry32 pseudo-random generator was ported to Python and run at B = 2,000 — it reproduces [+7.48%, +54.46%] exactly. That rules out a logic difference, a different seed, and a different trade set, and pins the entire gap on the resample count.

Why it is not unified: the JavaScript dashboard is a deliberately independent cross-check of the Python pipeline. Forcing the two to share a parameter would erode exactly the independence that makes the agreement meaningful. The dashboard labels the row MISMATCH on screen with both B values visible. The paper discloses both intervals and explains the gap.

6.3  What the evidence supports, and what it does not

6.4  Two open items, explicitly unresolved

The “190 qualifying indicator signals” denominator

The paper states that 25 of 27 OB-gated trades (92.6%) coincided with independent indicator signals, using 190 as the denominator. That 190 was derived under the indicators-only ablation's 1.5 × ATR entry-anchored stop — not the OB-gated strategy's own risk rules. The two populations are filtered differently. Do not cite 190 as settled. It is listed in the paper's own future-work section as something to either re-derive under the correct rules or drop.

The ablation reproducibility gap

See §6.1 — open, disclosed, with two named untested candidate explanations.

How spread out the numbers are around their average.
83Outlier+
A single observation far away from the rest, capable of dragging an average around on its own.
84Degrees of freedom+
Roughly, how much independent information a sample carries.
85Pearson r+
Strength of a straight-line association between two measurements, from −1 to +1.
86Spearman rho+
The same idea computed on rank order — catches any consistent trend, and resists outliers.
87Correlation is not causation+
Two things moving together does not establish that one causes the other. The hold-time/return association in §4.3 is reported as an association and nothing more.
88Bootstrap resampling+
Re-drawing your own data with replacement, many times, to see how much a result could have wobbled.
89With replacement+
After an item is drawn it goes back in the pot and can be drawn again. Without this, every re-draw would just be the original sample reshuffled.
90Confidence interval+
The range containing the middle 95% of those re-drawn results.
91Percentile+
The value below which a given share of results falls. The 2.5th and 97.5th percentiles are the two ends of a 95% confidence interval.
92Empirical p-value+
A p-value obtained by counting outcomes in a simulation rather than reading a formula — “what fraction of my thousands of simulated draws did at least this well?” See §4.6.
93Statistical power+
The chance a test would find a real effect that is actually there. The usual convention is 80%.
94Underpowered+
The test could not have found the effect even if it were real, so “no result” means “no information,” not “no effect.”
95Multiple comparisons+
Run enough tests and one crosses p = 0.05 by chance alone; an artifact, not a finding.
96Sampling distribution+
The spread of results you would get by repeating a measurement many times. A two-sample test needs one to exist; a single realised price path does not provide one, which is the reason Fisher’s and Welch’s tests were rejected here.
97Sharpe ratio+
Return per unit of total bumpiness, annualised. Higher is better.
98Sortino ratio+
Return per unit of downward bumpiness only — upside surprises are not penalised.
99Maximum drawdown+
The worst peak-to-trough fall in the equity curve. The number a human actually feels. See V-31.
100Equity curve+
Account value plotted over time.
101Annualised+
Rescaled to a per-year basis so periods of different lengths can be compared. It does not mean that amount was actually earned in a year.
102Risk-free rate+
The return available with no risk at all, normally a short-term government bond. Sharpe and Sortino here assume it is zero, which is disclosed and slightly flatters both.
103Time in market+
The share of all bars during which a position was open. 2.63% here, against 100% for both passive benchmarks — the single most important comparison caveat in this study.
104DCA (dollar-cost averaging)+
Buying a fixed dollar amount on a fixed schedule, regardless of price.
105Lump-sum buy-and-hold+
Buying once at the start and holding, untouched, to the end.
106Sleeve+
A small slice of a larger portfolio run under different rules from the rest. The defensible framing for this strategy is as a sleeve alongside DCA, never as a replacement for it.
107Monotonic+
Moving in one direction throughout, without peaking and reversing. The DCA-blend table improves monotonically across every split tested.
108Ablation+
Removing one component and re-running, to measure what that component was contributing. See V-37.
109Confounded+
Two possible explanations tangled together so neither can be credited on its own. Ablation arm 3 exists specifically to untangle entry selection from stop placement.
110Lookahead / data leakage+
Accidentally using information a real trader would not have had yet. The classic way a backtest flatters itself; bug 3 was a genuine instance.
111Out-of-sample+
Data the rules had never seen — here, genuinely postdating every code commit.
112Formulation period+
The period the rules were originally designed against. Explicitly NOT out-of-sample, and labelled as such everywhere it appears.
113Regime+
A stretch of market with a consistent character — rising (bull), falling (bear) or sideways (chop).
114Reconstruction+
A best-faith rebuild of an analysis whose original script was never saved. It reproduces the trade counts exactly but not the per-trade outcomes, and that gap is disclosed rather than papered over (§6.1).

Every one of these is also defined in plain language at its first use in Sections 1 through 6.

8.4  Two things this guide must never do

Rule 1

Never state or imply that the strategy “beats DCA” or “beats BTC” without the exposure-time figure (2.63% vs 100%) in the same sentence. Both passive arms won on raw terminal value in both windows tested.

Rule 2

Never imply that the retired per-criterion Fisher/Welch/MDE program (§2.4) is still part of the paper's reported findings. It was deliberately removed from both the code and the paper on 2026-08-27; the paper reports only the core win-rate claim and the three-arm ablation. Terms like Fisher's exact test and Welch's t-test may still appear, but only in their one legitimate remaining context: considered and rejected for the DCA/passive-benchmark comparison (§4.2).
